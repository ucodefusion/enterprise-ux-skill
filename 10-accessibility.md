# Accessibility and inclusive design

## Baseline
Target WCAG 2.2 AA where applicable. Prefer semantic HTML and native controls; use ARIA only where needed and follow established interaction patterns.

## Keyboard and focus
Support Tab, Shift+Tab, Enter, Escape and component-specific arrow keys. Ensure visible focus, logical order, no traps, dialog focus management and restoration.

## Names and status
Provide accessible names for icons, labels for fields, table headers, meaningful links and live announcements for important dynamic feedback.

## Visual access
Do not rely on colour alone. Check text/non-text contrast, zoom/reflow, reduced motion, readable typography and touch targets. Aim for generous targets; verify WCAG target-size requirements and exceptions.

## Alternatives
Provide keyboard alternatives to drag/drop and hover actions; captions or text equivalents where applicable. Test with keyboard and screen reader, not automated tools alone.
